# Hostel Maintenance Management System

A web app where students report hostel maintenance problems, administrators review and assign them, and maintenance staff log progress until the request is resolved and closed.

**Stack:** HTML/CSS/JavaScript front end, Express REST API, SQLite (better-sqlite3). Three-tier architecture: browser UI, Express API, SQLite database.

## Run it

```bash
npm install
npm start          # http://localhost:3000
npm test           # 39 API checks on a temporary database
```

Requires Node.js 18 or newer. The database file (`data/hostel.db`) and the demo data are created on first start. Delete the `data` folder to reset everything.

## Deploy on Render

Create a new Blueprint from this repository and select `render.yaml`. The Blueprint runs the app from `hostel-maintenance` and provisions a persistent disk for the SQLite database and uploaded photos. The disk requires a paid Render web service plan.

The Render configuration disables demo accounts and creates one administrator during first-time database initialization. Set `ADMIN_EMAIL` to the administrator's email and use Render's generated `ADMIN_PASSWORD` value (at least 16 characters) to sign in. Students can register through the app. Keep `SESSION_SECRET` generated by Render, and do not replace the persistent disk with ephemeral storage if you need to retain app data across deploys.

## Request lifecycle

SUBMITTED, UNDER REVIEW, ASSIGNED, IN PROGRESS, RESOLVED, CLOSED

| Step | Who | Action |
|---|---|---|
| Submitted | Student | Submits the request (optional photo) |
| Under review | Administrator | Starts review (optional) |
| Assigned | Administrator | Assigns a staff member, can adjust category and priority |
| In progress | Assigned staff | Starts work |
| Resolved | Assigned staff | Marks the work done |
| Closed | Student | Confirms the fix (or reopens it, which returns it to In progress) |

An administrator can also close a request as rejected or duplicate before it is assigned. Every step adds an update to the request history and sends a notification.

## Screens

Student: Login, Register, My requests, Submit request, Request detail, Notifications.
Administrator: Dashboard, Requests, Review, Reports, Hostels and rooms, User management.
Maintenance staff: My tasks and the update form.

## API

All routes except login, register and `GET /api/hostels` need `Authorization: Bearer <token>`.

| Method and path | Role | Purpose |
|---|---|---|
| POST `/api/auth/login`, `/api/auth/register` | public | Sign in, create student account |
| GET `/api/hostels` | public | Hostels and rooms |
| GET `/api/bootstrap` | any | Everything the signed-in user may see |
| POST `/api/requests` | student | Submit a request |
| POST `/api/requests/:id/review` | admin | Mark under review |
| POST `/api/requests/:id/assign` | admin | Assign to staff |
| POST `/api/requests/:id/reject` | admin | Reject or mark duplicate |
| POST `/api/requests/:id/update` | assigned staff | In progress or Resolved, with comment |
| POST `/api/requests/:id/comments` | student, staff or admin on the request | Add a comment |
| POST `/api/requests/:id/confirm`, `/reopen` | owning student | Confirm fixed or reopen |
| POST `/api/notifications/read-all` | any | Mark notifications read |
| POST `/api/hostels`, PATCH `/api/hostels/:id` | admin | Add hostel or room, rename hostel |
| POST `/api/users`, POST `/api/users/:id/toggle` | admin | Create staff or admin, activate or deactivate |

## Database

`hostels`, `rooms`, `users`, `requests`, `comments` (the request history), `notifications`. The schema is in `db.js`.

## Security notes

- Passwords are hashed with scrypt. Sessions use signed tokens that expire after 8 hours.
- Every route checks the caller's role on the server. SQL uses prepared statements only.
- Login attempts are limited to 10 per IP every 10 minutes. This is kept in memory and resets when the server restarts.
- Uploads are limited to PNG, JPEG, WebP or GIF under 2.5 MB and are saved under random file names.
- Set `SESSION_SECRET` in production. Run behind HTTPS.
